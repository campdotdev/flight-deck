# Factory sessions write only to their worktree and outbox

A factory session runs as the maintainer's macOS user, so it can reach the maintainer's own credentials. Sandboxed Bash read a Keychain item in a test, and the maintainer is on the ruleset's bypass list. A session that ran `git push origin main` with the maintainer's git login would get past the one approval that ADR 0005 made the hard stop. So no session holds a write credential. A session commits in its worktree and leaves an outbox: its handoff, its status move, and any PR body, media, or verdict. When the session exits, the runner checks the outbox against the stage's rules and makes every write in Linear and GitHub itself. Sessions get the Linear MCP server's read tools only and can't reach GitHub's hosts. Before check starts, the runner fetches what check needs from GitHub into the worktree. The runner never runs the repo's code. These limits defend against mistakes and against instructions planted in text the factory reads, such as a stranger's comment on a public PR. They don't defend against code that escapes macOS's sandbox, and they don't apply to a flow the maintainer runs by hand.

## Considered options

- **Sessions write to Linear through the MCP server, behind a hook.** A `PreToolUse` hook would check each `save_issue` and `save_comment` call against the stage's allowed moves, and the runner would still make the GitHub writes. A session that died halfway would leave a handoff half posted.
- **Sessions hold the machine user's token,** as earlier tickets assumed, behind deny rules, hooks, and rulesets. Deny rules match command text, so `Bash(git push *)` doesn't stop `git -C . push`. A session could also skip the machine user and ask `git credential-osxkeychain` for the maintainer's token.
- **The sandbox runtime (`srt`) around the whole `claude` process.** It confines file tools, hooks, and MCP servers too, and the subscription login worked inside it in a test. It is a beta research preview at v0.0.80. It doesn't handle a worktree whose git folder lives elsewhere, and Claude Code's own Bash sandbox can't start inside it. It can replace the built-in sandbox later without changing anything else here.
- **Sessions run as a second macOS user** with its own Keychain. That closes the Keychain gap. It needs admin rights, a second Claude login, and repos that both users can read.

## Consequences

- The runner pushes fast-forward only, and only after a build session, so check never pushes and no session writes to a spec branch. The runner also opens and edits the PR, attaches media, sets `flight-deck/check`, marks the PR ready, posts comments, and moves statuses. Earlier tickets gave those writes to build and check, and those stages still decide them.
- The runner's own code enforces the lifecycle from ADR 0006. A stage moves its issue from its working status to its handoff status or to Paused. Only the runner closes issues, in the two cases the lifecycle allows.
- A flow the maintainer runs by hand writes the same outbox and applies it with `flight-deck apply`, under the maintainer's own logins. The runner and hand runs share one write path.
- Every factory session runs in `dontAsk` with Claude Code's Bash sandbox on. `--settings` sets `allowUnsandboxedCommands: false` and `failIfUnavailable: true`, which makes the sandbox admin-required, so a repo's settings can't turn it off or loosen it.
- Sandboxed commands can't read under `~` except the paths the repo record reopens, and they reach only the hosts the record lists. `github.com`, `api.github.com`, and `uploads.github.com` are always denied. WebFetch runs outside the sandbox, so it gets the same host list plus documentation sites. Each extra MCP server exposes only the tools the record lists for it.
- MCP servers run outside the sandbox. For a repo with a web app, the browser MCP server is the one process a session drives that can load pages, and a proxy contains it instead of the sandbox (ADR 0009). Chromium can't start from sandboxed Bash on macOS, so a repo's own browser tests run only in CI until the sandbox can start a browser.
- Sessions load the repo's `CLAUDE.md`, skills, and subagents, and nothing that runs code. The runner passes `--setting-sources project`, `disableAllHooks: true`, and `--strict-mcp-config`, and it turns off auto memory and the claude.ai connectors. A repo's `env` block outranks the process environment, so the runner sets every variable it depends on in the `env` block of `--settings`. This replaces ADR 0002's `project,local`, because in a worktree `local` loaded the maintainer's own approvals from the main checkout.
- A sandboxed session can't write `.claude/settings.json` as a file, but it committed one through git plumbing in a test. A diff that touches `.claude/`, `.mcp.json`, the repo record, `CLAUDE.md`, or `AGENTS.md` pauses the issue before check, because check reads its instructions from the commit it judges.
- The install step is the session's first command, inside the sandbox, not a runner step. The runner runs git with hooks off. Worktrees come from a clone that Flight Deck keeps for each repo, so sessions can't move the maintainer's local refs.
- Before the runner sends anything, it scans each diff, PR body, and comment for credential patterns and for the exact values of the gitignored files it copied into the worktree. A hit pauses the issue. Sandboxed Bash can still read Keychain items, so the scan is the only backstop for them.
- Setup's ruleset on the default branch requires one approval and blocks force pushes and deletion. Factory branches get no rules.
- `flight-deck stop` turns on the pause switch, sends SIGTERM to every session, and pauses each session's issue without using up the stage's retry. SIGKILL would leave a session's background commands running. When the maintainer moves an issue out of its working status, the runner kills that issue's session at its next poll and discards the outbox.
- Nothing caps the issues the factory takes, because the maintainer sends each one. On an API key, the runner adds a daily cap to the monthly one. An issue that hasn't passed after its third verdict pauses.
