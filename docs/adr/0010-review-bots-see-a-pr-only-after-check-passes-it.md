# Review bots see a PR only after check passes it

Build opens every PR as a draft, and almost every common review bot skips drafts by default, including Copilot's automatic review, CodeRabbit, Codex, Greptile, Cursor Bugbot, Sourcery, and Claude. The factory leaves that default alone. Check starts once CI has finished on the head commit and waits for no bot. When check passes a commit, the runner marks the PR ready, and the bots review that commit then. Copilot's ruleset review, CodeRabbit, Claude Code Review, Qodo, Greptile, and Codex all review a draft when it's marked ready, and Cursor Bugbot and Sourcery did on the PRs observed. So a bot reviews only commits that check has passed, and a round that check sends back costs no bot reviews.

The maintainer still sees the bots' findings judged. If any bot left a finding on the head, the runner moves the issue from In Review back to Ready to check, and check judges the same commit again, with the bots' reviews as its only new input. That second verdict is the bot round. If no bot left a finding, no session runs.

## Considered options

- **Setup turns on draft review for each bot, and check waits for every bot on the draft.** This was the rule when the stages were first decided (ADR 0001). Every trip back to build would cost a review from each bot, and bots cap their re-reviews: CodeRabbit pauses after 5 reviewed commits, and Sourcery stops after 5 automatic re-reviews. Codex documents no draft setting at all.
- **Build opens the PR ready, and `flight-deck/check` alone says that check hasn't passed.** The bots would review every round here too, and GitHub would show the maintainer a ready PR that check hasn't judged.
- **Bot findings go to the maintainer untouched.** No session would run after check passes. The maintainer would sort every bot nitpick by hand, and on a public PR a stranger's comment can steer what a bot says.

## Consequences

- The runner starts check on a standalone issue once build's handoff is in and every check run and status on the head has finished, pass or fail. It doesn't wait for the review bots' checks or `flight-deck/check`. Of the check runs that share a name, only the newest counts, because Codacy never closes its first run. The runner reruns each failed workflow in full, once. If CI is still red and a failed run uploaded an artifact the record names, the runner starts build again instead of check, once per build handoff (ADR 0022). Otherwise red CI still starts check, so one verdict carries the CI failure with everything else check finds. If CI hasn't finished within the record's time limit, the runner pauses the issue, because only the maintainer can fix CI. A sub-issue's check doesn't wait for CI, so it starts at build's handoff, as in a repo with no CI (ADR 0004).
- The bot round is a verdict like any other. When it sends work back, the runner returns the PR to draft and sets `flight-deck/check` to `failure`, and the trip counts toward the loop cap of 3.
- The runner gains one move of its own: from In Review to Ready to check, when a bot leaves a finding on a commit that check passed. The runner's code enforces it with the rest of the lifecycle (ADR 0007).
- Check drops a bot finding with a reason of one or two sentences. The runner posts the reason as a reply in that finding's review thread and then resolves the thread (ADR 0020). A bot finding about security, auth, billing, user data, or migrations that check can neither prove nor dismiss with evidence pauses the issue.
- Each listed bot has a done rule, which reads the bot's done mark and holds its re-trigger. Flight Deck ships the rules, and the repo record names the bots (ADR 0016). Copilot's ruleset review fires only the first time a draft goes ready. The author's own Copilot setting fires every time: on Shaders, a second ready re-requested Copilot within 2 seconds, and it reviewed the new head. Because a ruleset review won't start again, the runner still sends a bot's re-trigger, such as a new review request or `@coderabbitai review`, each time it marks a PR ready after the first time. It does so whether or not the bot reviewed before, so a bot that missed the first ready, such as one out of quota, still reviews a later head.
- A bot that skipped, hit a rate limit, or timed out counts as "didn't review" for that commit, and the runner stops waiting on it.
- The spec PR takes the same path. The spec check passes, the runner marks the PR ready, and a bot round follows.
- The runner flags a change as ready for review only after its bot round settles (ADR 0011).
- Setup leaves each bot's draft review off. Gemini's is on by default, so setup proposes turning it off (ADR 0016). A bot reviews a factory PR only if the machine user qualifies for it. Copilot reviews automatically only the PRs of authors with access to Copilot code review, through a ruleset or the author's own setting, and Copilot Free doesn't include code review. On Shaders, the machine user needed its own Copilot plan, and Greptile skipped every PR the machine user opened (ADR 0016). CodeRabbit reviews only authors with a seat, and on a public repo with fewer than 10 stars it needs a manual trigger.
